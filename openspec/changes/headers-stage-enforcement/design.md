# Design

## Context

Verified in `proxy/addon.py`, `bin/tjor` and the pinned mitmproxy (12.1.2, `config/tjor.toml`) source:

- The addon's `request` hook does everything: verdict (`request_verdict(flow.request.pretty_url, host)`), 403, then for an allowed request identity handling (`_apply_identity`), broker and gateway injection (`_apply_broker`, `_apply_gateway`, keyed on `_logical_host`: `flow.server_conn.sni`, else `pretty_host`), and the #62 body scan. mitmproxy fires `request` once the whole body has been read. In `state_wait_for_request_headers`, `check_body_size` runs *before* the `requestheaders` hook and sets `flow.request.stream = True` when the declared body exceeds `stream_large_bodies`; right after the hook, `check_killed` runs, then `Expect: 100-continue` is answered with a `100` and the header removed, then `start_request_stream` opens the upstream connection (if the tunnel did not already) and sends the request headers, streams the body, and only then fires `request`. A chunked body has no declared size, is buffered, and streaming starts, headers first, once the buffer passes the threshold. `start_request_stream` raises `NotImplementedError` if a response has been set on a streaming flow; `server.py` logs that as "mitmproxy has crashed!" for the event and carries on (the buffered body is dropped, the next frames repeat the error, and the pending response is sent at the end of the message).
- The declared size comes from `expected_http_body_size`: `None` for a chunked request, the `Content-Length` when there is one, else `0`. Over HTTP/1.1 that is exact: mitmproxy's reader reads exactly that much, and `validate_inbound_headers` (on by default) rejects any other framing. Over HTTP/2 a request with no `Content-Length` reports `0` while DATA frames may still follow, so the hook cannot tell an empty body from an unbounded one. The `h2` library (4.3.0) resets a stream whose DATA exceeds a declared `Content-Length`.
- `flow.kill()` sets the flow's error; `check_killed` emits `ResponseProtocolError(KILL)`, whose HTTP/1 handling has no status code: the connection is closed without a response. Setting a response in `requestheaders` on a non-streaming flow makes mitmproxy consume the declared body and send the response without an upstream request.
- ALPN: with `http2=false`, mitmproxy's `alpn_select_callback` mirrors the upstream's negotiated protocol when the client offered it, and otherwise picks the first client offer among the HTTP/1 values; a client offering only `h2` gets `NO_OVERLAPPING_PROTOCOLS`, which is OpenSSL's "no acknowledgement": the handshake completes with no protocol, and a client that then sends the HTTP/2 preface is killed by the default `DisableH2C` addon ("prior knowledge … not supported"). An upstream that negotiates no ALPN (`b""`) is mirrored as no ALPN too, so a TLS fixture must advertise `http/1.1` for the client to see it.
- Upstream verification: `ssl_verify_upstream_trusted_ca`, when set, is loaded *instead of* the bundled `certifi` store (`create_proxy_server_context`), with hostname verification against the SNI unchanged. mitmproxy loads `config.yaml` from its confdir (`/home/mitmproxy/.mitmproxy`, the session's `proxy-ca/` mount) at start.
- Inside a CONNECT tunnel the inner HTTP layer runs in transparent mode: `flow.request.host` is the tunnel's server address (the #41 pinned IP after `server_connect`), the verified TLS server name is `flow.server_conn.sni`, and the tunnel's upstream connection is opened eagerly at CONNECT time. For an absolute-form request `flow.request.host` is the URL's host from the request line; mitmproxy clears `authority` on HTTP/1 before the hooks, so `first_line_format` cannot tell the shapes apart, but `flow.client_conn` is the same object (stable `id`) for a CONNECT flow and every flow inside its tunnel. `flow.request.host_header` is the `Host` header.
- `ensure_topology` (`bin/tjor`) writes the session policy and Corefile, computes the config hash, builds the proxy image, creates the internal network, runs `compose up -d proxy dns` (`--force-recreate` when the hash changed), waits for `proxy-ca/mitmproxy-ca-cert.pem` and copies it to `${TJOR_SESSION_DIR}/ca.pem`. `cmd_conformance` sets its environment, calls `ensure_topology`, starts the echo service and runs the conformance container, reading the probe summary from the output; its EXIT trap removes the temporary session directory. The conformance container (`python:3.13-slim`, stdlib only) is not given the proxy CA today; the echo fixture answers GET only, over plain HTTP, and is reachable under compose aliases. The launcher already requires `openssl` on the host (it pre-generates the proxy CA with it). Nineteen probes exist; every name is registered in `python/gen_boundary_matrix.py`.

## Goals / Non-Goals

**Goals:**
- No byte of a denied request is ever forwarded, for every request shape HTTP/1.1 can produce, and every allowed request is rewritten (credential, identity) before its first byte goes upstream.
- One host identity for the verdict, injection, identity handling and the resolved-address guard, bound to the connection rather than to a header the agent writes.
- A conformance proof whose upstream would notice a forwarded byte, with positive controls, and a host-side check that each closed connection was a denial by the expected rule.

**Non-Goals:**
- Any change to the matcher or to verdicts (`python/tjor_policy.py` is untouched).
- Scanning streamed bodies (#62 stays observe-only and bounded).
- Keeping HTTP/2 for HTTP/2-only protocols; see D2 for what that would take.

## Decisions

**D1. Verdict, denial, injection and identity move to `requestheaders`; one body rule decides between 403 and a closed connection.**
`requestheaders` derives the judged host (D3), computes the verdict with the existing `request_verdict` (IP guard included) on a URL rebuilt from that host, and stores it in `flow.metadata["tjor_verdict"]`. Allowed: `_apply_identity`, `_apply_broker`, `_apply_gateway` run here, so a streamed request's headers go upstream already rewritten. Denied: `_log_denial`, then: `expected_http_body_size(flow.request)` is `0` or a `Content-Length` at or below `stream_large_bodies` → remove `Expect` (so mitmproxy sends no `100 Continue`; the client sends or does not send its bounded body, mitmproxy consumes it, nothing is forwarded) and set the 403 as today; otherwise (`None` for chunked, or `flow.request.stream` already true) → `flow.kill()`, which closes the connection without a response before any body byte is consumed. The 403 path keeps the connection usable: a follow-up request on it is judged on its own. An upload the client interrupts after a 403 was set never sees the 403, but the denial was logged at the headers stage. What is guaranteed is "no byte of the request is forwarded": a tunnel's upstream connection, opened at CONNECT time, exists and stays idle; and one network read can hold headers and body, so "unread" is not claimed. `request` keeps `_scan_request_body` and asserts a verdict was recorded; if none is, it denies with `fail-closed:hook-error` (defense in depth). Both hooks keep the fail-closed wrapper (enforce first, log after); if `flow.kill()` raises because the flow is not killable, the wrapper falls back to the 403.

**D2. HTTP/1.1 only: a compatibility decision, stated with its cost.**
The rule in D1 is exact only when every request declares its body at the headers stage, which HTTP/1.1 guarantees and HTTP/2 does not: an HTTP/2 request without `Content-Length` looks empty to the hook. The proxy command gains `--set http2=false` next to `rawtcp=false`, and `--set validate_inbound_headers=true` to make the framing precondition explicit (mitmproxy normalises request-line whitespace before the addon sees anything, so the addon's own checks are on the parsed request, and the parser's validation is part of the contract). Consequences: every ordinary client (curl, gh, git, Go, Node, Python) offers `http/1.1` and falls back; a client offering only `h2` completes its handshake without a protocol and its preface is refused by `DisableH2C` (nothing is forwarded); gRPC and other HTTP/2-only protocols cannot be used inside the cage; HTTP/2 multiplexing is lost. Alternatives, recorded in ADR 0012: (a) keep HTTP/2 and kill every denied HTTP/2 request that declares no `Content-Length` — sound, but every bodiless denial over HTTP/2 (a GET or DELETE) loses its 403 page; (b) keep HTTP/2 and kill only undeclared-length requests whose method conventionally carries a body (POST, PUT, PATCH), answering 403 to the rest — keeps the page, HTTP/2 and gRPC, at two costs: a hostile client sending DATA on a GET past the threshold drives mitmproxy's late streaming switch into its "response already set" exception (one error log per megabyte, the body dropped, nothing forwarded, the 403 still sent at the end of the message), and the behaviour cannot be proven in conformance, because the fixture stack has no HTTP/2 upstream and mitmproxy mirrors the upstream's protocol to the client; (c) keep HTTP/2 and answer 403 relying on that exception as the backstop — rejected outright. (b) is the honest fallback if HTTP/2 inside the cage turns out to matter; its unit tests over fake flows would be the proof. The bodiless-denial argument against (a) is not an argument for `http2=false` and is not used as one.

**D3. One host identity: the tunnel target, recorded at CONNECT.**
`http_connect` records, for an allowed CONNECT, the canonical judged host under `flow.client_conn.id` in a module dict (`_tunnel_host`), removed in `client_disconnected`. `requestheaders` derives the judged host: with a recorded tunnel host, that host, which must equal `_canon_host(server_conn.sni)` when a TLS server name exists (mitmproxy verifies the upstream certificate against it, so this is the identity injection already trusts), else `fail-closed:host-mismatch`; without a tunnel, `flow.request.host`, the URL host from the request line. In both cases, when `flow.request.host_header` is present its host (`url.parse_authority`) must equal the judged host, else `fail-closed:host-mismatch`; an HTTP/1.0 request without `Host` is judged on the URL. The URL handed to the matcher is rebuilt from the judged host, `flow.request.scheme`, `flow.request.port` and `flow.request.path`, so `pretty_url` is no longer consulted for a security decision. `_logical_host` becomes this function and keeps serving injection, identity, the IP guard, the #62 scan and the log-volume counter. A plain-HTTP tunnel is judged on the CONNECT target like any other.

**D4. The fixture would notice: a recorder, a TLS listener, a conformance-only trust anchor.**
`echo.py` answers every method with `{"method", "headers", "body_len"}`, runs as a threaded server, and records every accepted connection and every request it starts reading — method, path, bytes received so far, complete or not — serving the record at `GET /_seen`, which is excluded from the record. A partial request shows as an incomplete entry; a connection that carried nothing shows as a connection. It also serves TLS on 8443 from `/tls/cert.pem` and `/tls/key.pem` when present, advertising ALPN `http/1.1` (the proxy mirrors the upstream's protocol; without it the client would see no ALPN at all). `cmd_conformance`, before `ensure_topology` starts the proxy, generates with the host's `openssl` a self-signed certificate with explicit extensions — `subjectAltName` listing `readonly.test`, `echo-noinject.tjor-test` and `echo-broker.tjor-test` (not `echo-inject.tjor-test`, the negative control), `basicConstraints=critical,CA:TRUE`, `keyUsage=critical,digitalSignature,keyEncipherment,keyCertSign`, `extendedKeyUsage=serverAuth`, two days — into `${TJOR_SESSION_DIR}/conformance-tls/`, copies the certificate into `${TJOR_SESSION_DIR}/proxy-ca/` and writes `proxy-ca/config.yaml` with `ssl_verify_upstream_trusted_ca: /home/mitmproxy/.mitmproxy/conformance-upstream.pem` (the container path). That file replaces the proxy's default trust bundle for the conformance session only; verification and hostname checking stay on, no conformance probe reaches a real TLS upstream, no other code path writes `config.yaml`, and the session directory is temporary. The echo service mounts `conformance-tls` at `/tls`; the conformance service mounts `${TJOR_SESSION_DIR}/ca.pem` (written by `ensure_topology`) at `/etc/tjor/ca/ca.pem` for the probe's TLS tunnels. `readonly.test` is added to the echo aliases and to `images/conformance/policy.toml` as a plain allow-listed host (the method gate's rules come with that change).

**D5. Eleven probes, each with a positive control where a negative is asserted, and a host-side denial-log check by count.**
Helpers: `via_proxy(url, method, headers, body, chunked)`, a plain-tunnel helper, a TLS-tunnel helper (`http.client.HTTPSConnection` with `set_tunnel` and the mounted CA), a `/_seen` snapshot helper, `closed()` recognising `RemoteDisconnected`, `ConnectionResetError` and `BrokenPipeError` while sending or reading, and `expect_denial(host, rule)` which prints `expect-denial\t<host>\t<rule>` and counts. Observation boundary for the recorder: snapshot `/_seen`, run the denied attempt, then send a sentinel allowed GET to the same fixture and take the second snapshot; the assertion is that nothing but the sentinel was added — a forwarded request precedes the proxy's answer to the client, which precedes the sentinel, so a late arrival cannot slip past. Probes (names as registered): (1) "enforcement: a large denied body is never forwarded" — positive control: a 2 MiB `Content-Length` POST to `echo-noinject.tjor-test` `/items` arrives complete with `body_len` 2 MiB; then a 2 MiB POST to `/phone-home/big` on the same host ends `closed()` and the record is unchanged; (2) "enforcement: a chunked denied body is never forwarded" — the same with chunked bodies, the denied one to `echo-inject.tjor-test` `/phone-home/chunked`; (3) "enforcement: a bounded denied request gets the 403 and the connection survives" — a 10 KiB POST to `/phone-home/small` is answered 403 with `x-tjor-rule: path-block` and a GET on the same connection returns 200; (4) "enforcement: a denied request with Expect gets no 100 Continue" — the probe sends headers with `Expect: 100-continue` and `Content-Length`, reads the first response line within two seconds, and asserts it is the 403, not a 100; (5) "enforcement: an interrupted denied upload is still logged" — headers for a 2 MiB `Content-Length` POST to a path-blocked URL, 64 KiB of body, then close; the denial is asserted through the log check; (6) "broker: a streamed request still receives the real credential" — a 2 MiB POST to `echo-broker.tjor-test` with a forged `x-agent-*` header arrives complete with the real token and without the header; (7) "host identity: a Host header inside a tunnel cannot steer the verdict" — plain CONNECT to `echo-noinject.tjor-test:8080`, inner GET with `Host: readonly.test` → 403 `fail-closed:host-mismatch`; (8) "host identity: an absolute-form Host header cannot steer the verdict" → `fail-closed:host-mismatch`; (9) "host identity: a TLS tunnel is judged on its server name" — TLS tunnel to `readonly.test:8443`, GET with matching `Host` → 200 from the echo, GET with `Host: echo-noinject.tjor-test` → `fail-closed:host-mismatch`; (10) "transport: HTTP/2 is not negotiated" — TLS tunnel whose ALPN offers `h2` before `http/1.1`: the negotiated protocol is `http/1.1` and the GET inside returns 200; (11) "transport: the conformance trust anchor does not disable upstream verification" — TLS tunnel to `echo-inject.tjor-test:8443` (not in the certificate's SAN): the handshake or request fails and no 200 arrives. Denial-log check: `cmd_conformance` collects the `expect-denial` lines, counts each `(host, rule)` pair, and after the run requires `denials.log` to contain exactly that many lines for each declared pair — probes 1, 2 and 5 provoke `path-block` on distinct hosts, so an unrelated failure in one of them cannot be covered by another — printing `denials: N/N expected rules recorded` and failing the run otherwise; probe helpers never retry a denied request, so counts are exact. The registry gains the eleven names (ten under `egress-policy`, the sixth under `credential-broker`); CI's `conformance` job reports 30 probes.

**D6. Docs, ADR, CHANGELOG, slides.**
README "Egress policy": a closed connection on a large or chunked request means a denial (`tjor denials` has the rule); the cage speaks HTTP/1.1 only, so gRPC and other HTTP/2-only protocols are unavailable inside it; a `Host` header that disagrees with the connection's host is denied. `docs/decisions/0012-headers-stage-enforcement-and-host-identity.md`: the three decisions (D1, D2 with the alternatives and the corrected facts about ALPN and bodiless denials, D3), the mitmproxy facts above, and the consequences (closed connections, no HTTP/2, the conformance trust anchor). CHANGELOG under `[Unreleased]`: Fixed (requests streamed past the 1 MiB threshold escaped path blocks and were forwarded with the placeholder credential and unstripped identity headers; a `Host` header could steer the verdict away from the connection's host), Changed (HTTP/1.1 only; a denied large or chunked request sees a closed connection; `Host` mismatches are denied), Added (eleven probes, the denial-log check, the TLS echo). Slides: the three tagged `egress-policy` re-read; "Policy has to see the request, not just the host" says the verdict is taken on the connection's host after TLS termination and before any byte goes upstream, over HTTP/1.1 only; pins updated.

## Risks / Trade-offs

- [A denied large upload now ends in a closed connection, not a 403] → the denial log records the rule; the README says what a closed connection means.
- [HTTP/2-only clients stop working inside the cage] → stated everywhere; alternative (b) in D2 is the documented fallback.
- [A client whose `Host` legitimately differs from its connection host] → none known; the denial names `host-mismatch`.
- [Moving injection to `requestheaders` changes the hook the existing tests drive] → tests move with it; the conformance suite proves the end-to-end behaviour on small, large, chunked and interrupted requests, over plain and TLS tunnels.
- [The conformance trust anchor replaces the proxy's bundle] → conformance session only, temporary directory, test aliases only, negative control (probe 11); `tjor run` never writes `config.yaml`, which a launcher grep in the task verifies.
- [Observation boundary] → the sentinel request orders the record; counts, not presence, decide the denial-log check.

## Migration Plan

No policy or config migrates. Rollback is reverting the change: enforcement returns to the `request` hook with the two defects. The method gate (`egress-method-gate`) is applied after this change is merged and builds on the hook, the judged host and the fixture.
