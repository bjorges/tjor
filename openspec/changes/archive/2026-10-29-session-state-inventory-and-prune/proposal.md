# Proposal

## Why

`tjor gc` never deletes session state directories — correct, and required by the session-lifecycle spec — but nothing else removes them or even lists them (#68). One directory accumulates under `session.root` per workspace × session name, throwaway test sessions included, and each can hold live secrets: the session proxy CA (`proxy-ca/`, `ca.pem`), broker material (`broker/`), harness auth (opencode's `home/.local/share/opencode/auth.json`, Claude Code's `home/.claude/.credentials.json`) and agent-minted `gh` tokens (`home/.config/gh/hosts.yml`, ADR 0007). `tjor reset` cleans one session at a time and only by a name the operator already knows, so on a developer machine the real inventory is `ls ~/.tjor/sessions` and guesswork (a machine that has run the integration suites holds two dozen such directories, most from sessions that no longer have a container). A boundary that keeps credentials out of the cage should not leave them lying in forgotten directories on the host.

Two existing behaviours stand in the way of doing this safely, and change with it: `resolve_session` creates the state directory for every command that names a session, so a lifecycle command with a mistyped `--session` leaves a ghost directory behind and refreshes the timestamps of a real one; and nothing serialises a launch against a deletion of the same session's state.

## What Changes

- **Launch records session metadata.** Every `tjor run` writes `meta.json` into the session's state directory (workspace, harness, profile name or directory, task id, first-launch and last-launch timestamps, launch count), atomically, with no secrets. Directories from older versions have no file and are shown as `unknown` where it would have supplied a value.
- **Lifecycle commands never create state.** `resolve_session` creates the state directory on the launch path only. `down`, `reset`, `status`, `denials`, `git-check`, `ls --state` and `prune` resolve the id without touching the disk, so a dry run or a mistyped name leaves nothing behind and bumps no timestamp.
- **A per-session lock serialises launch against prune.** `tjor run` holds a lock for the session from its first write into the state directory until the agent container exists; `tjor prune` and `tjor reset` hold the same lock around their check-and-delete. A launch and a deletion of the same session's state can therefore not interleave: whichever comes second is refused, loudly, naming the lock and its holder. The lock lives beside the state directory, never inside it.
- **`tjor ls --state` inventories the state root.** One row per state directory under `session.root`: session id, workspace (from `meta.json`), last activity (newest `lstat` time over the whole directory, never following symlinks; `unknown` when any part could not be read), whether the session has containers and in what state, and which known credential paths exist. Entries that are not real directories are reported, never descended. Like every lifecycle command it needs the container daemon.
- **`tjor prune` deletes state explicitly, and only state no container uses.** Exactly one selector: `--older-than <duration>` (every session whose last activity is older than the cutoff; unknown activity never qualifies) or one or more `--session <id>`; giving both, or neither, is a usage error. `--dry-run` lists exactly what a real run would remove; `--creds-only` deletes just the credential tier instead of the whole directory. A session with any container, in any state, is refused — `tjor down` removes them, and runs the teardown git check on the way. A session whose git-check marker is pending is refused for whole-directory deletion unless `--discard-unreviewed` is given, which is accepted only together with `--session`, so an age sweep never discards unreviewed evidence and the operator names each session whose findings they give up; `--creds-only` removes no evidence and is not refused by the marker. A container query that fails, or a lock held by a launch, refuses the session. Every deletion passes the existing symlinked-ancestor guard, rooted at the canonical session root (charter L26). Prune never runs implicitly; `gc` is unchanged and still never touches state.
- **One definition of the state tiers.** The `cache`, `sessions` and `creds` path lists that `tjor reset` owns today move into a small Python helper that `reset`, `ls --state` and `prune` all consult, so a credential path added for one command cannot be missed by the others. The credential tier is grounded in what the three harness images actually write, and the README states what it does not cover.

Not breaking: two new commands, one new flag, one additive file, and one new refusal — a launch while the same session is being pruned or reset, or a second launch of the same session before the first has created its agent container (today that second launch shares the first one's credentials and topology).

### Modified Capabilities
- `session-launch`: three new requirements — a launch records the session's metadata (`meta.json`) in its state root, atomically and without secrets, with older directories reading as unknown; lifecycle commands create nothing under the session root; a launch holds the session lock while it writes state.
- `session-lifecycle`: new requirements — the state root is inventoried (`tjor ls --state`) and pruned only explicitly (`tjor prune`), with the refusals above; the garbage-collection requirement's "never deletes state" invariant is unchanged and prune is the single path that does.
- `git-tamper-detection`: the pending marker's clearing rule gains one explicit exception — `tjor prune --session <id> --discard-unreviewed` removes the baseline and the marker together and says so; no age-based prune, credential-only prune or other command removes a pending marker.

## Impact

- `bin/tjor`: `resolve_session` no longer creates the state directory (launch does, after taking the lock); new `session_lock_acquire`/`session_lock_release` helpers; `cmd_run` takes the lock before its first write, writes `meta.json` before `ensure_topology`, and releases the lock once the agent container exists; `cmd_ls` gains `--state`; a new `cmd_prune` (dispatch + `usage`); `cmd_reset` reads its tier paths from the helper and takes the lock around its deletion.
- `python/tjor_state.py` (new): tier path lists, duration parsing, inventory (metadata, credential flags, last activity by `lstat`), `\x1f`-separated output for bash; unit-tested under `python/tests/`.
- Tests: `tests/integration/lifecycle_test.sh` gains a live section (lifecycle commands create nothing; inventory of a legacy and a current directory; refusal on running, stopped and absent-daemon containers; pending-marker refusal and `--discard-unreviewed`; symlink-ancestor refusal; dry run; real prune; `--creds-only`; held and stale locks; a launch and a prune interleaved both ways through a test-only hold seam); `python/tests/test_state.py` for the helper; the existing reset tier checks guard the refactor.
- Docs: README "Managing sessions" (commands, residuals: what the credential tier does not cover, the lock's pid-reuse residual, prune forgets rather than revokes), `CHANGELOG.md` under `[Unreleased]`, the lifecycle slide (re-read and re-pinned for the changed specs), the three spec deltas synced at archive.
- Not affected: the cage, the proxy, the images, `gc`, `down`, the boundary matrix (the lifecycle suite is not a probe suite).
