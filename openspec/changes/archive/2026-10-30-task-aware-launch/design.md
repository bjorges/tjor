# Design

## Context

Verified against the pinned images (`tjor-agent-*:local`, `--network none`, `--help` and small probes), 2026-10-30:

- **opencode 1.18.28** (yargs): top-level `--prompt [string]`, `-c/--continue`, `-s/--session <id>`. Sessions live in SQLite: a real session home (`~/.tjor/sessions/<id>/home/.local/share/opencode/`) holds `opencode.db`, `opencode.db-wal`, `opencode.db-shm`, `snapshot/`, `log/` and no `storage/` directory; `opencode db` is a subcommand. The sessions tier of `tjor_state.py` names `storage` and `log` only.
- **Claude Code 2.1.260** (commander): `[prompt]` positional, `-c/--continue` ("the most recent conversation in the current directory"), `-r/--resume [id]`, `--session-id <uuid>`, `--add-dir <directories...>` variadic. Probes: `claude -p --add-dir /tmp hello` reports no prompt (the variadic swallowed `hello`); `claude -p --add-dir /tmp -- hello` delivers it; `claude -p -- --version` treats `--version` as the prompt; **`claude -- mcp` opens the `mcp` subcommand**, so `--` does not stop subcommand dispatch of a bare first operand. Transcripts: `home/.claude/projects/<cwd with every non-alphanumeric as ->/<uuid>.jsonl`, beside `memory/` in the same per-project directory.
- **Copilot CLI 1.0.83** (commander): `-i/--interactive <prompt>`, `--continue`, `-r/--resume[=value]`, `--session-id <id>`; `-p/--prompt` is non-interactive and not used. Session store: `home/.copilot/session-state` (the installed package source names it; a real session home was not available).
- The command reaches the container as argv: `cmd_run` builds `agent_cmd` and `run_agent` passes it to `compose run -d … agent "$@"`; the entrypoint `exec`s it. No shell, no environment variable carries it. The whole command line is therefore visible to `docker inspect` and to the process list inside the cage.
- `cmd_run` order today: options, `resolve_session`, session root and lock, `--dir` gates, notes gate, `--dir-ro` gates, `task_notes_prepare` (creates the notes directory), self-mount checks, profile gate, **first write** (`mkdir home`), profile stage, `prepare_broker` (mint), gateway, secret scan, image, collision guard, metadata, `ensure_topology`, command, `run_agent`.
- The state directory's root is not mounted by the Compose layout: it binds `home`, `ca.pem`, `policy.toml`, `proxy-ca`, the log files, `Corefile` and `conformance-tls` individually. `--unsafe-dir`, however, overrides the sensitive-path gate for the workspace and `--dir`, and tjor's roots (session root, ancestors, descendants) are in the sensitive set only: a launch from the home directory with `--unsafe-dir`, or `--dir ~/.tjor --unsafe-dir`, mounts the state directory writable.

## Goals / Non-Goals

Goals: an owned command line from the operator's own config; a task prompt that is data on every harness; resume without reading harness internals, from a record the agent cannot write; refusals that create nothing; the record and the stores under one reset tier; drift caught at the pin. Non-goals: profile-carried arguments (deferred, see the proposal); interpreting `args` beyond the exact collision rule; any knowledge of what the agent should read on start (profile instructions own that, per the issue); hiding the prompt from container inspection.

## Decisions

### D1. One builder, a bash array, a NUL-separated test seam

`build_agent_cmd <harness>` is a bash function in `bin/tjor` that fills the global array `AGENT_CMD`, the string `AGENT_CMD_NOTE` ("fresh, prompt sent" / "fresh, no prompt" / "continuing the conversation recorded <time> for task <id>") and the flag `AGENT_CMD_RECORD` (whether `run_agent` writes the record). The explicit-command branch (`$# -gt 0`, with or without `--`, unchanged `*) break`) sets `AGENT_CMD=("$@")` and skips the builder entirely. `agent_cmd_print` writes the array NUL-separated for the docker-free test, which sources the launcher's functions as `task_notes_test.sh` does. No newline framing anywhere, so a multi-line prompt is one element like any other.

### D2. Arguments: user config, validated by a helper whose exit status is checked

`cfg harness.<name>.args --default '[]'` yields JSON; `python3 python/tjor_launch.py args --harness=<name> [--adding=continue] [--adding=prompt]` reads it on stdin, validates (list; each a non-empty `str`; no NUL, no newline; ≤ 65536 bytes; not `--`) and prints one entry per line, exit 2 with a message naming the position and rule otherwise. Because entries are newline-free and non-empty, the line form is exact, and bash reads it as `out="$(…)" || die`, then `mapfile -t ARGS <<<"${out}"` when `out` is non-empty: the producer's exit status is checked before the array exists (`mapfile < <(…)` would not propagate it). Every helper receives values in the attached form (`--task=<id>`, `--template=<t>`, `--task-dir=<d>`), so a dash-leading value is a value to argparse too. The collision rule is exact: with `--adding=continue`, an entry equal to `--continue` or `-c` refuses; with `--adding=prompt`, an entry equal to `--prompt`, starting with `--prompt=`, equal to `-i` or `--interactive`, or starting with `--interactive=` refuses, per harness. Nothing else is looked at: tjor does not know the harnesses' flag sets, says so, and the spec states what an entry can do without tjor noticing. `harness` joins `USER_ONLY_TABLES` and `SECURITY_TABLES` in `tjor_cfg.py`; the drop warning is generalised ("user-config only; ADR 0013/0014"); an unapproved file keeps today's whole-file untrusted warning (the drop runs only on the trusted layer).

### D3. Prompt rendering in Python, captured with a sentinel

`python3 python/tjor_launch.py render --template=T --task=ID [--task-dir=DIR]` scans the template left to right: `{{` → `{`, `}}` → `}`, `{task}` → id, `{task_dir}` → DIR (refused when absent), any other `{` or `}` refuses naming the offending text; the result must hold no NUL, be ≤ 65536 bytes, and contain at least one whitespace and one non-whitespace character (the one-word rule from the Claude finding, applied to every harness so a template behaves alike; the README says so next to the template). bash captures it as `p="$(python3 … && printf x)" || die; p="${p%x}"`, which keeps trailing newlines and the helper's exit status. The template is validated only when it is used (a launch with `--task` and `prompt` set), as `notes_dir` is today. The id grammar is unchanged by `prompt`: the attached forms make a dash-leading label inert on both the helper and the harness side.

### D4. Delivery table

| harness | arguments | prompt (fresh) | continue |
|---|---|---|---|
| opencode | `args…` | `--prompt=<p>` | `--continue` |
| claude | `args…` | `-- <p>` | `--continue` |
| copilot | `args…` | `--interactive=<p>` | `--continue` |

Order: harness, `args…`, continue flag, prompt. The attached forms rely on documented parser behaviour (yargs and commander read everything after the first `=` as the value); the TUIs need a terminal, so the live test checks what tjor passes (`docker inspect … .Config.Cmd`), not the harness's parse. Claude Code's `--` is verified above. `-c` is not used because Copilot CLI has no short form.

### D5. The launch record

`conversation.json` at `${TJOR_SESSION_DIR}/conversation.json`: `{"schema": 1, "harness": "claude", "task": "a", "started": <epoch>}`, exactly those keys and types. `python3 python/tjor_state.py conversation-read DIR` does `os.lstat`: `ENOENT` → prints nothing, exit 0 (the only "no conversation"); a symbolic link, FIFO, directory or other non-regular file, a size over 4096 bytes, an `open(O_NOFOLLOW)` failure, invalid JSON or a shape mismatch → exit 2 with the reason, and the launch refuses naming the file. On success it prints `harness<US>task<US>started`. `conversation-write DIR --harness=H --task=T` writes atomically (mkstemp in DIR, `os.replace`), like `meta.json`, replacing whatever was there. Written in `run_agent` after `compose run` returned the container id and before `session_lock_release`, only when `AGENT_CMD_RECORD` is set (the builder ran with `--task` and `prompt` set or `resume = "auto"`). Read in the builder under the lock (taken right after `resolve_session`). Decision: `auto` and record (harness, task) equal (this harness, this task) and no `--no-resume` → continue; else fresh.

**Never agent-writable.** The builder refuses when the launch relies on the record and an **intended** writable root covers the state directory. The intended roots at that point are `TJOR_WORKSPACE`, every `TJOR_EXTRA_DIRS` entry (both already physical) and `TJOR_TASK_DIR` (resolved, possibly not yet created): `task_notes_prepare` later appends the notes directory as a writable extra, so a template such as `/safe/notes/{task}` with the session root at `/safe/notes/a/sessions`, launched with `--unsafe-dir` from an unrelated workspace, would otherwise pass the overrideable notes gate, see no covering root in the builder, and then mount `/safe/notes/a` writable over the record. Worktree common directories are not in the set: `worktree_common_dirs` refuses one that is, contains or lies under a tjor root through a `dir_is_sensitive` check that has **no** override, and the plan relies on that check by name (spec scenario "Worktree common directories").

The state directory usually does not exist at the insertion point (only the session root and the lock do; `home/` is the first write), so the check is a read-only helper, `python3 python/tjor_launch.py covers --root=P --state-root=R --session=S` (R the physical session root, `TJOR_LOCK_ROOT`; the state directory is `R/S`), exit 0 covers, 1 not, 2 error → refuse. Algorithm, never creating anything and never following a link: `lstat(P)`; a link or a non-directory is an error. If P exists: covers iff P is, by `(st_dev, st_ino)` along the parent chain, `R/S` or an ancestor of it when `R/S` exists, else R or an ancestor of R (since `R/S` is one component below R, an ancestor-or-self of R is the only way to contain a missing `R/S`). If P does not exist: walk up to its deepest existing ancestor E with missing suffix T (each step `lstat`, directories only, a link is an error); P can then cover `R/S` only when both are missing and E is R by identity and T equals S, because every ancestor of an existing directory exists. Any `OSError` other than `ENOENT` on the walk is exit 2. Identity on the existing part catches a differently-cased or differently-composed spelling of the session root on a filesystem that treats them as one directory; the string compare is confined to the one component that does not exist yet. `python/tjor_task.py`'s `contains` is the model but is not reused as is: it treats a missing path as an error. Only `--unsafe-dir` can produce a covering mount set, and the refusal names the root, the record and the two ways out (drop the coverage, or set `[task]` back to its defaults / pass an explicit command). A `--dir-ro` root covering it is allowed: the record holds nothing secret and a read cannot change the decision. Residuals stated: the record says tjor started a conversation, not that the harness still holds one; it can be absent or stale after a crash between container creation and the write, after an explicit command, or after a conversation switch inside the harness.

`TIERS["sessions"]` gains `conversation.json`, `home/.local/share/opencode/opencode.db`, `…-wal`, `…-shm`, `home/.copilot/session-state` (the existing `storage` and `log` entries stay for older homes). `home/.claude/projects` is deliberately not added (memory lives there); the README states it.

### D6. Trust and provenance

`[harness]` is user-only for the reason ADR 0013 gives for `[task]`: approval reviews content, not consequence, and the consequence of repo-set harness flags is a steered agent (a prompt flag) or a relaxed harness (`--auto`, `--dangerously-skip-permissions`, `--allow-all-tools`) in every clone, which tjor elsewhere treats as meaningful (the root-owned managed opencode config, the `.opencode` mask). ADR 0014 records it and extends the general rule: no key a repository can set shapes the harness launch. The `repo-config-trust` requirement that names the user-only tables is modified to name both, keeping its header; the trust slide gains ADR 0014. The structural cage is unchanged either way; this is about not handing the repository the harness's own controls.

### D7. Ordering in `cmd_run`

options (`--no-resume` added; `--harness` checked against the three names before `resolve_session`) → `resolve_session` → session root and lock → `--dir` gates → notes gate → `--dir-ro` gates → **`build_agent_cmd`** (reads config, renders the prompt from the resolved `TJOR_TASK_DIR`, reads the record, checks writable coverage over workspace, `--dir` roots and the intended notes directory) → `task_notes_prepare` (first creation outside the state directory) → worktree common dirs (their own no-override sensitive check) → overlap and self-mount checks → profile gate → first write → profile stage → mint → … → `ensure_topology` → launch line → `run_agent` → container exists → record write → lock release. A refusal in the builder therefore creates nothing: no notes directory, no state-directory content, no credential, no sidecar; the session root and the lock already exist (every launch sets them up first), and `resolve_session` may already have queried Docker for a qualified-looking `--session`. The `session-launch` "lifecycle commands create no session state" rule holds: the builder reads, never writes.

### D8. The launch line

`tjor: harness command: claude --model opus -- <prompt: 142 bytes>` then `tjor: conversation: fresh, prompt sent` or `tjor: conversation: continuing the one recorded 2026-10-29 14:02 for task a (tjor's decision; the harness decides what --continue finds)`. The prompt never reaches the terminal (it may be long and hold anything the template holds), but it is in the container's command line and the README says so; `args` are printed through the sanitizer.

### D9. Flag drift at the pin

The Dockerfile's harness stage runs, after each install, `<cli> --help` and checks with `grep -F --` for the literal flags tjor uses: opencode `--prompt` and `--continue`; claude `--continue` and `[prompt]`; copilot `--interactive` and `--continue`. A miss fails the build naming the harness and the flag. A Renovate bump that renames a flag is caught where the pin changes, not at an operator's launch.

### D10. Proof

- `python/tests/test_launch.py`: `args` rules and collisions; `render` placeholders, escapes, refusals, bounds, the one-word rule; dash-leading values through the attached forms; `covers` with a missing state directory, an existing one, a symlinked root (error), a case-variant alias of the session root (covers), a component-boundary sibling (`/safe/notes/a-other`, not), a missing root whose final component equals the session id (covers), a missing root elsewhere (not), and that nothing is created.
- `python/tests/test_state.py`: the record round trip; absent vs link vs FIFO vs oversize vs wrong shape (exit codes); the extended tier list.
- `python/tests/test_config_ergonomics.py`: a trusted repo cannot set `[harness]` (warning names file and table; the check reports it); an unapproved file keeps the whole-file warning; an unknown key under `[harness.claude]` and a nested `[harness.cluade]` refuse.
- `tests/integration/harness_launch_test.sh` (docker-free; a docker shim that records and fails any call; plain session names only, so the resolver never queries Docker): per harness the built command for args / prompt / continue / `--no-resume` / explicit command with and without `--`; refusals (unknown harness, bad entries, collisions, bad template, `{task_dir}` without notes, invalid `resume`, corrupt record, writable coverage through the workspace, through a `--dir` and through an uncreated notes directory over the session root) each asserting "nothing new": no state directory and no notes directory for the fresh fixtures, and for the corrupt-record fixture that the existing directory and record are byte-identical afterwards; in every refusal the shim was never called. Registered in `gen_boundary_matrix.py` and run by both CI unit jobs.
- Live, in `lifecycle_test.sh` under opencode: fresh detached launch → the session's agent container (found by the `tjor.session` and `tjor.role=agent` labels, since the proxy and DNS services share the session label) has `Cmd` `[opencode, --print-logs, --prompt=…]` and the record exists; `tjor down`, relaunch → the new container's `Cmd` is `[opencode, --print-logs, --continue]`; `down`, `--no-resume` → the prompt again; `tjor reset sessions --dry-run` lists the record; after the reset the next launch is fresh; an explicit `-- opencode --help` leaves the record byte-identical. These prove argv transport and the record lifecycle, not that the harness parsed the prompt or continued.

## Risks / Trade-offs

- **Attached-form parsing is documented, not executed here.** The TUIs need a terminal; the live test checks tjor's side. Mitigation: D9 catches a flag disappearing; a parse change is a residual stated in the README.
- **A record without a conversation, or no record for a conversation.** The harness crashed before its first message, the operator cleared its store, tjor died between container creation and the write, an explicit command or an in-harness switch started a newer conversation: `--continue` then meets nothing or something else (Claude Code 2.1.260 exits with an error in print mode; the others were not exercised). Remedy and residual stated: `--no-resume`, `tjor reset sessions`.
- **`args` can change the harness's mode** (`--resume`, `--session-id`, a positional, a subcommand name, a cluster such as `-ic…`, a parser abbreviation): the collision rule is deliberately literal and small; the spec says what it does not see and the launch line reports tjor's decision only.
- **The prompt is in the container's command line.** `docker inspect` and the in-cage process list show it; the launch line's redaction is for the terminal and logs only. Stated.
- **Shared session home.** Without `session_per_task` the record is per session and `--continue` reaches only the most recent conversation; stated.
- **`--help` grep.** Formatting changes could fail a build spuriously; the check names what it looked for, and the fix is a one-line edit at the same pin bump.
- **Copilot store path** comes from the package source, not an observed home; the tier entry is harmless when absent, and the live proof is under opencode.

## Migration

None. Defaults are empty `args`, empty `prompt`, `resume = "never"`; no record is written unless a prompt or `auto` is configured; an explicit command is untouched. The only visible changes without configuration are that `--harness <unknown>` now refuses instead of launching opencode, and that `tjor reset sessions` removes two more stores.

## Implementation notes (post-review, head after `6a2942b`)

- `tjor_launch.py covers` exits **3** for "not covered" (not 1), and so does `tjor_task.py contains` (second review round): Python's own exit for an uncaught exception, or for a crash before `_main` runs, is 1, and the launcher must never read a fault as "no". Both helpers turn any unexpected exception into a refusal exit, and every caller proceeds only on 3.
- The one missing component in `covers` is compared by its Unicode canonical caseless form (NFKC, casefold, NFKC), so a notes template such as `/root/PROJ-{task}` beside the session `proj-a` is refused on every filesystem, a case-sensitive one included (stated in the spec and the README); a link anywhere in the root's chain is refused, whether the leaf or the state directory exists or not; the launcher passes the notes directory's **physical** intended path (`TJOR_TASK_PREFIX/TJOR_TASK_REL`).
- Config values reach the builder as JSON (`tjor_cfg get --json`), so a value's type and every byte (an escaped NUL, a trailing newline) survive the shell and are judged by the helper. `render` reads the template JSON from **stdin**, not an argument: `json.dumps` ASCII-escapes, so a legal 44 KB prompt of non-ASCII text is 132 KB of JSON, over the 128 KiB Linux allows one argv element, and `execve` would have failed before the helper could say why (second review round).
- The record reader opens with `O_NONBLOCK`, `fstat`s the descriptor against the `lstat`, reads in a bounded loop, requires `schema` to be an `int` and bounds `started`; the writer flushes the file before the rename and the directory after it (`F_FULLFSYNC` where offered, else `fsync`; best effort, the record is not a boundary); `conversation-write` failures, `OSError` included, exit 2 like a bad read.
- The one-word rule applies to the stripped prompt (`mcp\n` is still `mcp`); `--no-resume` with an explicit command warns that it has no effect; the record-write failure message says an older record may still stand.
- The Dockerfile flag check matches flag names as whole tokens and reports a CLI that crashes under `--help` with its exit status and output; it is a check on names, not on attached-form behaviour (stated residual).
- Third review round: `covers` and `tjor_task.py contains` refuse a `.` or `..` component and a relative path before any walk (a lexical `..` would hide a link above it), and `contains` walks both chains with `lstat`, refusing a link anywhere rather than following it; the coverage check in `task_notes_prepare` passes the notes directory's physical path. Both stdin readers in `tjor_launch.py` are bounded (8 MiB; more refuses). `_flush_dir` swallows only EINVAL/ENOTSUP/EBADF and lets an I/O error propagate; the flush helpers have direct tests. The check-to-mount window (a component swapped after the check, by a writer outside tjor's lock, which the engine resolves again) is a stated residual in the README and both specs.
- Fourth review round: `TJOR_TASK_DIR` is the notes directory's **physical** path (resolved prefix plus the components below), so the sensitive gate, both coverage checks, the `--dir-ro` compare, the mount, the scan, the probe and `{task_dir}` all use one spelling; before, the checks judged the physical directory while the mount used the template's spelling. The path rules both helpers share (`plain_path`, `lstat_dir`) live in `python/tjor_paths.py`. `ENOSYS` joined the tolerated directory-fsync errnos (`DIR_FSYNC_UNSUPPORTED`, tested one by one); the stdin bound is tested at the bound and one over; the caseless form's D146 claim is a test over every assigned code point.
