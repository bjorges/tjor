# Proposal

## Why

`--task <id>` is a label today: `TJOR_TASK_ID` in the cage, a `tjor.task` container label and a term in the proxy config hash (#69). It has no filesystem effect. Task-oriented work keeps its notes and hand-off files in a per-task directory, usually inside one larger notes repository (`~/scratch/tasks/<id>/`), and the only way to give the agent that directory today is to launch from it, which makes git discovery climb to the notes repository's root and mount the **whole notes repository**, writable, as the workspace: every other task's files are exposed, and the real code repository is no longer the workspace, so its trusted `.tjor/policy.toml` and `.tjor/config.toml` are not read and the harness's `AGENTS.md` and skill discovery look in the wrong tree. The alternative, `--dir ~/scratch/tasks/<id>`, works but has to be typed on every launch and gives the session no per-task identity, so two tasks in one repository share one session.

## What Changes

- **A per-task notes directory, opt-in by user configuration.** A new `[task]` section (`notes_dir = "~/scratch/tasks/{task}"`, `create`, `session_per_task`) makes `--task <id>` resolve a notes directory from the template and mount it **writable through the existing extra-dir path**, so it inherits the sensitive-path gate, the VM-share check, the mixed-writability and self-mount rules, git trust as a tree, the launch-time mask discovery and the git-check baseline. Workspace resolution is unchanged. The section is read from the defaults and the user config only: a trusted repository config cannot set it (no config key creates a writable host mount today, and this one must not become the first), and a misspelled key under it aborts the launch like a misspelled `[landlock]` key. `TJOR_TASK_DIR` names the directory inside the cage; no wire header is derived from it.
- **The task id is a path and a session name now, so it is checked like both.** When a notes directory is configured or `session_per_task` is enabled, the id must be lower-case, dot-free and at most 32 characters (`[a-z0-9][a-z0-9_-]{0,31}`): no `.`/`..`/hidden names, one spelling per directory on case-insensitive and case-sensitive hosts alike, and a name that fits the session grammar without truncation. The template is confined: normalised, no `.` or `..` components, the placeholder inside one component. The directory is resolved without side effects, then, on the launch path only and in a fixed order (gate the intended path, create or validate under the session lock, judge coverage, mount if uncovered, scan), created component by component below the fixed prefix with descriptor-relative, no-follow steps; the prefix itself is never created; a symbolic link below the prefix refuses the launch.
- **Refusals that keep the notes repository out of the cage.** A launch is refused, with no override, when the workspace is the notes root (the fixed prefix) or an ancestor of it, judged by inode ancestry rather than string comparison so a case-insensitive or Unicode-normalising filesystem cannot fail it open. A notes directory already covered by a writable root is still created, validated and scanned, but not mounted twice; one under a read-only root is refused by the existing writability rule. The VM-share check for the directory is a correspondence check: its parent is bound into a throwaway container, which must see the directory by name.
- **One session per task.** With `session_per_task = true`, a launch with `--task <id>` and no `--session` uses the id itself as the short session name (it already fits the grammar), so `tjor down --session <id>`, `status`, `denials` and `reset` address it with what the operator typed; an explicit `--session <name>` names the session as today and `--task` stays the label and the directory, which is how two harnesses work one task concurrently. An id the lifecycle resolver would read as another session's qualified id (equal to or prefixed by this workspace's base id, or naming an existing session's full id) is refused at launch, so the round trip holds. `tjor attach --task <id>` picks the running agent carrying that `tjor.task` label.
- **A loud warning for credential-shaped files.** Before the agent starts, the notes directory is scanned, bounded and without following links, for names shaped like credentials and for the secret shapes the egress tripwire knows; findings are named in a warning, and a scan that stopped at a bound or could not read a file says so instead of reading as clean. A warning, not a refusal: the directory is the operator's own.
- **Docs and proof.** A `task-notes` capability spec and problem slide; README "Task notes" with the residuals (the directory is writable and git-trusted like any `--dir`; it is shared by every session launched with the same task id; what the agent writes there reaches the host, nested repositories, links and committed secrets included; the bind source is handed to the engine as a path, so a swap after the checks is outside what the launcher can see); the `[task]` keys in the packaged defaults; a docker-free launcher test, a pytest suite for the helper, one live case in the multi-repo test, and a live two-task Compose lifecycle case (two sessions up, one down, the other untouched).

Deferred, with the reviewers' reasons recorded in the design: `--workspace <dir>` (changing directory before parsing re-bases relative arguments, and the lifecycle commands would need it too), `--notes-workspace` (a second workspace mode with its own git, cwd and lifecycle questions; the notes mount stands on its own), and `--task` on the lifecycle commands (the short name is the id, so `--session <id>` is the same keystrokes without guessing a harness).

Compatibility. Without a `[task]` section nothing changes: `--task` stays a label with today's grammar, `--session` derivation, `attach` and the lifecycle commands behave as before. With `notes_dir` set, an id outside the new grammar is refused with a message naming the grammar.

## Capabilities

### New Capabilities
- `task-notes`: the per-task notes directory: configuration and its provenance, id and path validation, launch-only creation, the writable mount and its inherited guards, the notes-root refusal, `TJOR_TASK_DIR`, the credential-shaped-file warning, the stated residuals.

### Modified Capabilities
- `session-launch`: named session derivation gains the per-task short name and the launch-time refusal of ids that would not round-trip.
- `session-lifecycle`: reattachment accepts `--task <id>`.
- `session-identity`: no identity header is derived from `TJOR_TASK_DIR`.
- `repo-config-trust`: approved repo values layer over the user config except for the user-only `[task]` table; a misspelled key under it aborts. ADR 0013 records that repository configuration never names a host path to mount.

## Impact

- `bin/tjor`: `cmd_run` (resolution, the launch-only creation after the gate and lock, the covered-root check, the mount through `TJOR_EXTRA_DIRS`, the scan), `resolve_session` (id grammar, the per-task short name, the inode-based notes-root refusal), `cmd_attach` (`--task`), usage text.
- New `python/tjor_task.py` (template validation and side-effect-free resolution, descriptor-relative creation, inode ancestry, the scan) and `python/tests/test_task.py`; `python/tjor_cfg.py` (user-only table, `task` in the security tables) and its tests.
- `compose.yaml` (`TJOR_TASK_DIR` in the agent environment); `config/tjor.toml` (`[task]` defaults).
- `tests/integration/task_notes_test.sh` (docker-free, registered in `python/gen_boundary_matrix.py`), cases in `tests/integration/multirepo_test.sh` and `tests/integration/lifecycle_test.sh`, `ci.yml` (the new test in the unit job).
- README, CHANGELOG, `docs/decisions/0013-repo-config-never-mounts-host-paths.md`, `slides/presentations/overview/slides.md` (new problem slide and map entry; four re-pinned slides).
